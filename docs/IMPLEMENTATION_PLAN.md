## Context

BracIT's BRD (`docs/TenderSense_BRD.pdf`) describes a tool that watches procurement portals (e-GP Bangladesh, World Bank STEP), matches tenders against a company's capability profile by meaning (not keywords), applies hard eligibility rules, grades matches S/A/B/C, explains why, and delivers a ranked daily shortlist. The BRD is written as an internal 7-day hackathon build for BracIT only.

The product owner wants it built as a **multi-company SaaS**: a company registers, logs in, sets up its capability profile + bidding criteria (eligibility rules) + notification emails, then receives matched tenders in-app and by email. The repo is greenfield (IDE files, the BRD, a vendored shadcn skill at `.claude/skills/shadcn/`).

### Assumptions (not asked; flag if wrong)
- One capability profile per organization.
- Members can browse the whole shared tender pool, but only see their own org's match/eligibility/decisions.
- Tender **attachments (PDF bidding documents) are not downloaded or parsed in v1**; extraction runs on notice title/description/detail-page fields only. This is the single biggest quality lever left for v2.
- Bangla-language notices are embedded as-is (Gemini embeddings are multilingual); no translation UI in v1.
- "Today" shortlist = matches computed since the last digest for that org.
- Soft rules affect grade/recommendation only; hard rules decide eligibility.

## Research findings that shape the design (verified 2026-09-09)

**Gemini** (`google-genai` 2.22.x, pin `<3.0`):
- Embeddings: `gemini-embedding-2` (fallback id `gemini-embedding-2-preview`), `output_dimensionality=768`, truncated vectors auto-normalized. It does **not** accept `task_type`; use prompt prefixes: documents `"title: {title} | text: {body}"`, queries `"task: search result | query: {text}"`. Legacy `gemini-embedding-001` (task_type based) as configurable fallback.
- Generation: `gemini-3.1-flash-lite` (marketed for structured JSON extraction) as default; `gemini-2.5-flash-lite` as cheapest alternative. Structured output via `GenerateContentConfig(response_mime_type="application/json", response_schema=PydanticModel)` → `response.parsed`. Model ids are config, recorded per row.
- Free-tier limits are only visible in AI Studio; assume ~15 RPM for Flash-Lite. Use `aiolimiter` + `tenacity`.

**World Bank** — no auth, verified JSON:
`GET https://search.worldbank.org/api/v2/procnotices?format=json&apilang=en&rows=100&os=0&srt=noticedate&order=desc&fl=id,notice_type,notice_status,noticedate,submission_deadline_date,submission_deadline_time,project_id,project_name,project_ctry_name,sector,procurement_group,procurement_group_desc,procurement_method_code,procurement_method_name,bid_reference_no,bid_description,notice_text,notice_lang_name,contact_name,contact_organization,contact_email`
Always pass `fl` (omitting it can 500). Server-side date filters are unreliable → poll newest-first and stop at already-seen ids. Detail URL `https://projects.worldbank.org/en/projects-operations/procurement-detail/{id}`. Optional bulk backfill: Finances One dataset DS00979.

**e-GP Bangladesh** — no Cloudflare, no captcha, no login for listing/detail. RSS is dead. The listing is an AJAX servlet returning server-rendered `<tr>` HTML:
`POST https://www.eprocure.gov.bd/TenderDetailsServlet` with `funName=AllTenders&viewType=Live&departmentId=&office=&procNature=&procType=&procMethod=0&tenderId=0&refNo=&pubDtFrm=DD/MM/YYYY&pubDtTo=DD/MM/YYYY&closeDtFrm=&closeDtTo=&cpvCategory=&isFrame=&pageNo=1&size=100&h=t` (hidden inputs `totalPages`, `noRecordFound`). Detail: `GET /resources/common/ViewTender.jsp?id={id}` (ministry, PE, nature/type/method, ref, package description, CPV category, publication/closing dates, tender security, eligibility text, brief description, doc fee, lots, corrigenda). **So the primary e-GP adapter is httpx + HTML parsing; Playwright is a fallback adapter only if the servlet gets blocked.** Old JSP stack, undocumented → keep selectors in DB config, store raw HTML for reprocessing.

### Data model (key tables)
Conventions: UUIDv7 PKs, timestamptz, tenant tables carry `org_id` with composite indexes leading with it.

- **Identity**: `users` (citext email, nullable password_hash, email_verified_at, is_superuser), `oauth_accounts`, `auth_tokens` (verify/reset, hashed, single-use), `refresh_sessions` (hashed, family_id, rotation/reuse detection), `organizations` (slug, country, plan, timezone), `memberships` (role admin|member), `invitations` (hashed token, 7d).
- **Shared pool**: `tender_sources` (code, adapter_key, schedule_cron, config jsonb selectors, health), `tenders` (unique(source_id, external_id), title/summary/description, procuring_entity, country, method, category, published_at, deadline_at, currency, estimated_value, status, content_hash, version, portal_metadata jsonb, generated tsvector; indexes on deadline, published, GIN tsv/trgm), `tender_documents` (raw listing row / detail HTML / api JSON stored gzip on a volume via `BlobStore`), `tender_extractions` (versioned AI attributes + per-field confidence + evidence quotes, is_current), `tender_embeddings` (vector(768), chunk_kind title_summary|scope_requirements, model, HNSW cosine).
- **Profile**: `company_profiles` (overview, sectors[], geographies[], turnover + currency + year, keywords[], completeness, version), `profile_services`, `profile_past_projects`, `profile_certifications` (canonical codes), `profile_embeddings` (facet_kind overview|service|past_project|sector_geo, vector(768)).
- **Rules**: `rule_sets` (one active per org), `rule_set_versions` (definition jsonb, immutable per version), `fx_rates` (money comparisons across BDT/USD).
- **Matching**: `tender_matches` (unique(org_id, tender_id); similarity + breakdown, grade, eligibility_status + per-rule results jsonb, recommendation, urgency, explanation jsonb/text + kind templated|llm, inputs_fingerprint, profile_version, rule_set_version_id, extraction_id, thresholds_version, instant_notified_at), `tender_match_history`, `tender_decisions` (is_current, history), `rule_overrides` (per-tender "verified pass/fail" by a user).
- **Notifications**: `notification_settings` (per org: inapp, instant + min grade, digest time/timezone/min grade, reminder offsets default {7,2}), `notification_recipients` (verified_at, unsubscribe token, types[]), `notifications` (in-app), `email_outbox` (rendered at enqueue, status, attempts, dedupe_key unique), `notification_ledger` (unique(org, type, subject_key) idempotency).
- **Ops**: `job_runs`, `scraper_runs`, `ai_usage`, `audit_log`, `matching_config` (thresholds, weights, model ids, embedding mode).

### Matching pipeline
1. **Profile embedding**: one vector per facet (overview, each service, each past project, sector+geo), query-prefixed. Re-embed only facets whose text hash changed.
2. **Tender embedding**: chunk A = title + entity + category + method + description (doc-prefixed); chunk B = extracted scope/deliverables/qualifications (after extraction).
3. **Extraction** (Flash-Lite, temperature 0, `response_schema=TenderAttributes`): sectors, category, method, estimated_value, min_annual_turnover, required_certifications, eligible_countries, min_years_experience, similar_projects_required, jv_allowed, bid_security, deadline, scope_summary, key_deliverables, required_qualifications_text, plus `confidence{field}` and `evidence{field: quote}`. Portal metadata wins over AI for deadline/method/entity.
4. **Score**: `f_i = max over chunks cos(facet_i, chunk)`; `sim = 0.6*max(f_i) + 0.4*mean(top3 f_i)`. Optional hybrid keyword term via `ts_rank` (config flag). Per-org exact scan (cheap at MVP scale); HNSW reverse lookup on `profile_embeddings` once orgs > few hundred.
5. **Grade** defaults S ≥ 0.78, A ≥ 0.70, B ≥ 0.62, else C. `scripts/calibrate_thresholds.py` fits these on the labeled set and writes `matching_config` (bumping `thresholds_version` re-grades without AI calls).
6. **Eligibility** (deterministic engine): per rule pass|fail|unknown|warn; overall `ineligible` if any hard fail, `needs_verification` if any hard unknown, else `eligible`. Extraction confidence < 0.5 ⇒ unknown ⇒ rule's `on_missing` (default verify).
7. **Urgency** from deadline in org timezone: expired / critical ≤3d / high ≤7d / normal ≤21d / low / unknown.
8. **Recommendation** matrix: S/A + eligible → bid; S/A + needs_verification → hold; B eligible/verify → hold; C → skip; any ineligible or expired → skip.
9. **Explanation**: always a templated one from structured data; Gemini explanation (structured JSON: summary, why_matched[], gaps[], risks[], next_step) only for S/A or eligible B, regenerated only when grade or eligibility status changes. Daily token budget guard → fallback to templated.
10. **Idempotency**: `inputs_fingerprint = sha256(profile_version, rule_set_version_id, extraction_id, embedding model, thresholds_version, tender.content_hash)`; skip if unchanged. Profile/rules change → debounced `rematch_org` (ARQ `_job_id`), open tenders only. Tender content change → new version, re-extract/embed, rematch all orgs, in-app "tender updated" for orgs with a current bid decision.

### Rule builder contract (shared by backend engine and frontend UI)
`GET /rules/catalogue` returns attributes, operators, presets; `GET /rules/schema` returns JSON Schema generated from the Pydantic models so the UI validates client-side.

```jsonc
// rule_set_versions.definition
{ "schema_version": 1, "combinator": "all",
  "rules": [
    { "id": "r_turnover", "template": "min_annual_turnover", "label": "Turnover requirement within our capacity",
      "attribute": "min_annual_turnover", "operator": "lte",
      "value": { "source": "profile", "field": "annual_turnover" },     // or {"source":"literal","data":...}
      "severity": "hard", "on_missing": "verify", "enabled": true },
    { "id": "r_certs", "attribute": "required_certifications", "operator": "subset_of",
      "value": { "source": "profile", "field": "certification_codes" }, "severity": "hard", "on_missing": "pass" },
    { "id": "r_countries", "attribute": "eligible_countries", "operator": "intersects",
      "value": { "source": "literal", "data": ["BD","NP"] }, "severity": "hard", "on_missing": "verify" },
    { "id": "r_value", "attribute": "estimated_value", "operator": "between",
      "value": { "source": "literal", "data": { "min": {"amount":100000,"currency":"USD"}, "max": {"amount":5000000,"currency":"USD"} } },
      "severity": "soft", "on_missing": "pass" },
    { "id": "r_exclude", "attribute": "full_text", "operator": "not_contains_any",
      "value": { "source": "literal", "data": ["demolition"] }, "severity": "hard", "on_missing": "pass" }
  ] }
```
Attribute catalogue v1 (type → operators): `min_annual_turnover`, `estimated_value`, `bid_security` (money: lte|gte|between, FX-normalized), `required_certifications`, `eligible_countries`, `sector` (list: in|not_in|intersects|subset_of), `country`, `procurement_method`, `procurement_category`, `language` (enum: in|not_in), `min_years_experience`, `similar_projects_required` (int: lte|gte), `jv_allowed`, `local_registration_required` (bool: eq), `full_text`, `title`, `procuring_entity` (text: contains_any|not_contains_any), `deadline_at` (datetime: within_days|after). Each attribute declares its data source (portal_metadata | ai_extraction | derived) and profile bindings. Presets: turnover within capacity, certs we hold, eligible countries include ours, contract value in range, exclude keywords, preferred methods, sectors of interest. Engine output per rule: `{rule_id, label, status, tender_value, expected, reason, source, confidence}`. `POST /rule-sets/preview` evaluates a draft against the last N (capped 2000) tenders → pass/fail/verify counts + samples.

### Background jobs: ARQ + Redis
Async-native (matches FastAPI, asyncpg, `google-genai` aio, Playwright async), built-in cron, retries, `_job_id` dedupe. Processes: `api`, `worker` (default queue, owns crons), `worker-scrape` (queue `scrape`, max_jobs=1; Playwright image only if the fallback adapter is enabled, otherwise slim image). Every task wrapped in `@tracked_job` → `job_runs`.

```
cron per source      scrape_source → upsert_tender (store raw first) → if new/changed: process_tender
process_tender       extract_attributes → embed_tender → match_tender_all_orgs → generate_explanations → notify_instant (ledger-guarded)
on profile/rules     rematch_org(org_id, reason)   (30s debounce via _job_id)
cron */15 min        digest_dispatcher: orgs whose local time hits digest_time and last_digest_sent_for < today → send_daily_digest
cron hourly          deadline_reminder_sweep: current bid decisions with days_to_deadline in offsets → in-app + email (ledger)
cron every minute    email_outbox_pump (FOR UPDATE SKIP LOCKED, batch 50, backoff 1m/5m/30m/2h/12h)
cron daily 02:00     close_expired_tenders, refresh_fx_rates, purge_old_job_runs, mark_source_health
```

### Auth
- argon2id via pwdlib; password ≥10 chars.
- Access JWT HS256, 15 min, claims `sub, org, role, jti, typ`. Active org in the token; `POST /auth/switch-org` re-issues. (Chosen over URL org slugs to keep the SPA simple; one org per user is the common case.)
- Refresh: opaque 256-bit, sha256 in `refresh_sessions`, rotating, family reuse detection, 30 d sliding, `HttpOnly; Secure; SameSite=Lax; Path=/api/v1/auth` cookie. SPA keeps access token in memory only; single in-flight refresh + replay on 401.
- Email verification required before creating/joining an org. Reset revokes all sessions. Redis rate limits on `/auth/*`.
- Google: authlib server-side authorization-code flow (`/auth/google/start` → `/auth/google/callback`), nonce/state in signed cookie, link by `(provider, sub)` then by verified email, redirect to SPA `/auth/google/callback` which calls refresh.
- Deps: `CurrentUser`, `CurrentOrgContext`, `require_role("admin")`, `require_superuser`.

Security decisions worth knowing:

- Registration, login, forgot-password and resend-verification answer
  identically whether or not an address exists, so none of them can be used to
  discover who has an account.
- No raw secret is stored. Verification links, reset links, invitations and
  refresh tokens are kept as SHA-256 digests, asserted by a test.
- Refresh tokens rotate on every use. Presenting an already-rotated token is
  treated as theft: the whole token family is revoked and everyone must sign in
  again. The revocation is committed before the error is raised, because the
  request session would otherwise roll it back.
- Access tokens carry the active organization, but membership is re-read on
  every request, so removing a member takes effect at once rather than when
  their token expires.
- Google sign-in links to an existing local account only when Google reports the
  address as verified; otherwise anyone could claim someone else's address.
- Login, registration, password reset and verification resends are rate limited
  in Redis. Redis being unavailable allows the request rather than locking
  everyone out.
- Creating or joining an organization requires a verified address, so an
  organization's tender notifications can never be routed to an address nobody
  proved they own.

**M2 Tender pool — backend done.** The shared pool schema ships in migration
`0003_tender_pool`: sources with their scraping configuration and health,
tenders, raw documents, versioned AI extractions, and vectors. Verified against
Postgres: the generated search vector updates when a notice is amended, the same

over the HNSW index. The migration chain rebuilds from an empty database.

Two things worth recording:

- Alembic renders pgvector columns without importing pgvector, so migrations
  fail with a `NameError`. The Alembic environment now emits the import for any
  vector column, which covers every future migration too.
- Raw portal payloads are gzipped into a volume rather than stored in Postgres.
  When a portal changes its markup, parsing is replayed over stored bytes
  instead of re-scraping, which matters because these portals are slow, rate
  limited, and sometimes remove closed notices. Storage keys are sanitised
  because they are partly derived from portal-supplied identifiers.

Ingestion is one path. Scrapers, the JSON and CSV importer, and the admin "add a
tender" endpoint all call the same upsert, so an imported notice behaves exactly
like a scraped one. Identity is the portal plus its own identifier. A notice
whose content hash is unchanged only has its "last seen" timestamp touched,
which is what stops a daily scrape re-running the language model over thousands
of unchanged rows. The hash deliberately ignores portal metadata, because these
sites rewrite view counters and render timestamps on every request.

The demo dataset is 40 synthetic notices generated deterministically, spanning
strong fits, near misses and clear rejects for a sample Dhaka systems
integrator, with relevance labels for evaluating matching later. It includes the
awkward cases on purpose: five notices withhold their value, two have no
deadline, four are already closed, and three close within three days.

Demonstrated against the running stack: browse 40 notices sorted by deadline
with days remaining, keyword search, filter counts for the sidebar, and source
health. Keyword search for "management information system" returns two notices,
which is the baseline semantic matching has to beat in M3.

One defect found and fixed: an unknown sort field was correctly rejected by the

bad value. Sort fields are now an enum, and any model built from user input

## Risks
- e-GP servlet is undocumented and on an old stack; may change or start blocking. Mitigations: selectors in DB config, raw HTML stored + `reprocess`, Playwright fallback adapter, World Bank proven first.
- Gemini free-tier throttling during seeding; model id churn (`gemini-embedding-2` vs `-preview`). Mitigations: rate limiter, model ids in config, recorded per row, `AIClient` abstraction with fake.
- Threshold calibration on ~40 synthetic tenders is weak evidence; grow labels from real bid/skip decisions.
- Extraction hallucination → never fail eligibility without evidence + confidence; low confidence ⇒ verify.
- Deliverability depends on operator's SPF/DKIM for the SMTP domain.
- Single-VM memory if Playwright fallback is enabled (cap scrape worker at 1 job, 2 GB, `init: true`).
